# Publishing the provider

Everything below is a one-off, done by hand by an owner of the GitHub org. After it, a
release is just `git tag vX.Y.Z && git push origin vX.Y.Z`: the Release workflow builds,
signs and uploads it, and both registries pick it up on their own.

What is already in the repo:

- `.github/workflows/release.yml`: GoReleaser on `v*` tags. Builds 13 OS/arch zips, the
  `SHA256SUMS`, its GPG signature and the `manifest.json` the registries need.
- `.github/workflows/ci.yml`: `go vet`, `go build`, `goreleaser check`, a stale-`docs/`
  check, and the acceptance test against the in-memory fake API under both Terraform and
  OpenTofu.
- `docs/`: generated by tfplugindocs from `templates/` and the schema, in the layout the
  Terraform Registry renders.

## 1. Pick the namespace (do this first)

The registry namespace is the GitHub owner of the repo, lowercased. Customers write
`source = "<owner>/pagerly"`.

| Repo lives at | Customers write | Notes |
|---|---|---|
| `Pagerly/terraform-provider-pagerly` | `pagerly/pagerly` | **Recommended.** The `Pagerly` org already exists on GitHub (created 2022, no public repos). Matches the Go module path, `main.go`, the README and the dashboard/landing copy. |
| `Falit/terraform-provider-pagerly` (today) | `falit/pagerly` | Every `pagerly/pagerly` in `main.go`, README, `docs/`, `templates/`, the dashboard and the landing site would need changing. |

To move it: GitHub → the repo → **Settings → General → Danger Zone → Transfer ownership**
→ new owner `Pagerly`, repo name unchanged. Then locally:

```bash
git remote set-url origin git@github.com:Pagerly/terraform-provider-pagerly.git
```

Also in the `Pagerly` org settings:

- **Actions → General**: allow GitHub Actions, including actions from `actions/`,
  `hashicorp/`, `opentofu/`, `goreleaser/` and `crazy-max/`.
- **Third-party access (OAuth app policy)**: if it is restricted, approve **Terraform
  Registry** after the first sign-in in step 5, or the `pagerly` namespace won't show up.

## 2. Create the signing key

The Terraform Registry only accepts **RSA or DSA** keys. Make one just for releases:

```bash
gpg --quick-gen-key "Pagerly <hello@pagerly.io>" rsa4096 sign never
```

It asks for a passphrase; keep it. Get the fingerprint (the 40-hex-character line):

```bash
gpg --list-secret-keys --keyid-format=long hello@pagerly.io
```

Export the public key (this goes to both registries, and is safe to share):

```bash
gpg --armor --export <FINGERPRINT> > pagerly-signing-key.asc
```

Back up the private key and the revocation certificate gpg printed
(`~/.gnupg/openpgp-revocs.d/<FINGERPRINT>.rev`) in the password manager. If the key is lost, a
new one has to be added to both registries before the next release.

## 3. Add the repo secrets

GitHub → the repo → **Settings → Secrets and variables → Actions → New repository secret**:

| Name | Value |
|---|---|
| `GPG_PRIVATE_KEY` | output of `gpg --armor --export-secret-keys <FINGERPRINT>` (the whole block, `-----BEGIN PGP PRIVATE KEY BLOCK-----` included) |
| `PASSPHRASE` | the key's passphrase |

The workflow reads the fingerprint from the imported key, so there is no fingerprint secret.

Or with `gh`, if your token can see the repo (the `Pagerly` org rejects fine-grained tokens
that live longer than 366 days):

```bash
gpg --armor --export-secret-keys <FINGERPRINT> | gh secret set GPG_PRIVATE_KEY --repo Pagerly/terraform-provider-pagerly
gh secret set PASSPHRASE --repo Pagerly/terraform-provider-pagerly
```

## 4. Make the repo public and cut v0.1.0

1. Commit and push the workflow, docs and this file, and check the **CI** run on `main` is green.
2. **Settings → General → Danger Zone → Change visibility → Public.** The history has been
   checked for secrets; the only personal data is `falit@pagerly.io` in `examples/full/main.tf`.
3. Tag and push:

   ```bash
   git tag v0.1.0
   git push origin v0.1.0
   ```

4. Watch **Actions → Release**. The GitHub release `v0.1.0` should have 13 `.zip` files,
   `terraform-provider-pagerly_0.1.0_SHA256SUMS`, `…_SHA256SUMS.sig` and
   `…_manifest.json`. It must not be a draft.

## 5. Terraform Registry

1. Go to <https://registry.terraform.io>, **Sign in** with GitHub, and grant the
   **Terraform Registry** app access to the `Pagerly` org (approve it in the org's OAuth
   policy if asked).
2. **User Settings → Signing Keys → New GPG Key**. Namespace `pagerly`; paste
   `pagerly-signing-key.asc`. Do this before publishing; the registry checks the
   `v0.1.0` signature against it.
3. **Publish → Provider**, pick `Pagerly` / `terraform-provider-pagerly`, accept the terms,
   **Publish**. The registry adds a webhook to the repo, so later tags publish on their own
   within a few minutes.
4. Check <https://registry.terraform.io/providers/pagerly/pagerly/latest/docs> shows
   the docs.

## 6. OpenTofu Registry

OpenTofu has its own registry, populated from GitHub issues on `opentofu/registry`:

1. <https://github.com/opentofu/registry/issues/new/choose> → **Submit new Provider**.
   Repository: `Pagerly/terraform-provider-pagerly`. A bot validates it and opens a PR,
   and a maintainer merges it, usually within a day.
2. Same page → **Submit new Provider Signing Key**. Namespace `pagerly`, paste
   `pagerly-signing-key.asc`. It has to be filed by a member of the `Pagerly` org; make
   your membership public if the bot can't see it.
3. After the merge, new tags are picked up on their own (within about an hour).

## 7. Check it works

```hcl
terraform {
  required_providers {
    pagerly = {
      source  = "pagerly/pagerly"
      version = "~> 0.1"
    }
  }
}
```

```bash
terraform init
```

```bash
tofu init
```

Both should download `pagerly/pagerly v0.1.0` and say the signature is valid.

## 8. After it's live

The dashboard, the landing docs at <https://www.pagerly.io/docs/terraform> and the help
centre still say "early access, email hello@pagerly.io". Change them to point at
`registry.terraform.io/providers/pagerly/pagerly`.
