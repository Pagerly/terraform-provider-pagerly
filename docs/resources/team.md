# pagerly_team (Resource)

A team. Its on-call comes either from a round-robin **rotation** that Pagerly runs, or from
an external schedule it **sync**s with: PagerDuty, Opsgenie, Datadog On-Call, JSM Ops or
Google Calendar. Set exactly one of `rotation` or `sync`. People are given as emails.

## Example Usage

```hcl
resource "pagerly_team" "payments" {
  name          = "Payments"
  timezone      = "Europe/London"
  slack_channel = "C0123456789"

  rotation = {
    users      = ["alice@example.com", "bob@example.com"]
    frequency  = "Weekly"      # Hourly | Daily | Weekly | BiWeekly | Monthly
    day        = "Monday"      # weekday; or Monday-Friday / Monday-Saturday / All 7 Days for Daily & Hourly; or 1–31 for Monthly
    time       = "09:00"
    start_date = "2026-10-20"
  }

  reminder = {
    type = "Every Rotation"    # Daily | Weekly | Custom | Every Rotation
  }
}
```

### Synced from PagerDuty (or Opsgenie, Datadog, JSM Ops, Google Calendar)

```hcl
resource "pagerly_team" "platform" {
  name          = "Platform"
  timezone      = "UTC"
  slack_channel = "C0123456789"

  sync = {
    source      = "pagerduty"   # pagerduty | opsgenie | datadog | jsmops | gcal
    schedule_id = "PABC123"     # the schedule's id in that tool
  }
}
```

The source must already be connected under **Scheduling Integrations** in Pagerly. The
schedule id is checked against the source when the team is created or the id changes, so a
typo fails the apply instead of creating a team nobody is paged from. Pagerly keeps the
on-call in step with the source on its usual schedule; `current_oncall` shows the last read.

Changing `schedule_id` or `source` updates the team in place. Switching between `rotation`
and `sync` recreates the team. Removing `reminder` turns the reminder off; removing
`user_group` detaches it. Deleting the resource soft-deletes the team (recoverable from the
dashboard).

## Schema

### Required

- `name` (String) Team name, unique in the workspace.

### Optional

- `custom_slack_message` (String) Custom on-call change message.
- `daily_message_time` (String) Time of day the daily on-call message is sent, `HH:mm`.
- `jira_board` (String) Jira board linked to the team.
- `manager_id` (String) Slack user id of the team's manager.
- `reminder` (Attributes) Shift reminder. Remove the block to turn reminders off. (see [below for nested schema](#nestedatt--reminder))
- `rotation` (Attributes) A Pagerly round-robin rotation. Set exactly one of `rotation` or `sync`; switching between them recreates the team. (see [below for nested schema](#nestedatt--rotation))
- `show_change_notification` (Boolean) Post a message in the channel when on-call changes.
- `slack_channel` (String) Slack channel id the team's on-call updates are posted to.
- `sync` (Attributes) Follow an external schedule instead of a Pagerly rotation. The source must be connected under Scheduling Integrations in Pagerly. Set exactly one of `rotation` or `sync`. (see [below for nested schema](#nestedatt--sync))
- `timezone` (String) IANA timezone the rotation hands over in, e.g. `Europe/London`. Required with `rotation`; optional with `sync`, where the source's own schedule decides the times.
- `update_slack_topic` (Boolean) Keep the channel topic in step with who is on call.
- `user_group` (String) Slack user group id (`S…`) whose membership Pagerly keeps in step with who is on call. Remove the attribute to detach it.

### Read-Only

- `current_oncall` (String) Email of whoever is on call as of the last read. Informational.
- `id` (String) Team id.
